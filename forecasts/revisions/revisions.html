Key findings

    Every week's revisions

    Each week's data release reports a new week and revises earlier ones. The chart compares each week's first report, the same week one release later, and its value in the latest data.

    Release by release (national)

    “Previous newest week” is the week that was newest in the prior release; its revision is the change between its first and second reports. “Older weeks” sums the national changes to all earlier weeks. States revised counts states whose previous newest week (or any older week) changed.

    How long revisions take

    How far a report is from the latest data, by how many weeks old it is when reported (lag 0 = the newest week). Positive means the report was later revised up.

    Is revision size linear in the count?

    Newest-week reports from states since the current reporting period began. If revisions were proportional to the count, points would follow a line of slope 1 on this log-log chart; if they were pure count noise, slope ½.

    Size of revision vs size of report
    Which form fits the spread of revisions?

    Fitted to log-scale revisions after removing the size+growth shift. Proportional: a fixed share of the count. Count noise: grows like √count. Power law: grows like count1−k. Lower AIC is better.

    Nowcast models, replayed week by week

    For each past release, each model was fit using only data versions available at that time, used to nowcast that release's two newest weeks, and scored against the latest data. Lower is better for errors and WIS; coverage should be near 50% and 90%. The highlighted row has the lowest WIS.

    none: report kept, revision uncertainty only. constant (previous model): fixed shift and fixed s.d. per lag. size: shift depends on report size. size+growth: also on the week-over-week change. Unless marked “constant s.d.”, the s.d. follows the power law in report size. Error and CRPS are on the log scale; WIS is on the data's own scale, from 23 quantiles.
